Static map (CoreUIComponents.dll, WindowManagement.dll and twinapi.appcore 26100, read with their PDBs):
- ConnectionComplete gate. ConnectNavigationTask sends ConnectionComplete only after the task's target
  state (+0x3bc) reaches 10. The target state is set by SessionLayer::NavigateToView (0x3294c). Mapping
  from ViewNavigationLevel to target state: 0->10, 1->0, 2->0xc, 3->0xb, 4->0xd, 5->5; any other level
  throws ProtocolException 0x4c.
- Phaseout. IsViewManagerPhaseoutEnabled (CoreUI 0x2ab14, WM 0x2d944) is TRUE for device family 3
  (Desktop), which is what Wine returns. Under phaseout:
  - the server path (CreateView, then IMSA 0x47250) creates the task but skips
    NotifyRequestNavigateToView;
  - it navigates the task itself only when get_IsDefaultNavigationUsed is true, which is a phone-shell
    path;
  - ActivationBypass does nothing.
  -> H5 (the CoreUI ViewActivator navigates) is REFUTED.
- Native navigating actor (HYPOTHESIS: the trigger is not pinned down). Explorer's WindowManagement
  ViewManagerBridge does the following:
  - Connect (0x47c18): CoreUIFactoryCreate; FindTypeID({490C6BC3-8AB2-4528-B974-709A9EF2D72D});
    CreateMessageProxy(L"System\\NavigationServer_ShellViewManager"); AddProxyListener; QI {490C6BC3};
    the same again for ClientViewCreator.
  - OnConnected (0x480a0): proxy AddEventListener(listener, type), then GetViews (slot 5), then
    AddListListener on the list.
  - After that it calls IShellViewManager::NavigateToView (slot 14: viewId, level, direction 0,
    animation 1).
  - ViewManager::NavigateToView (0x326d4) finds the task with FindTaskByInstanceId(viewId).
- Flat ABI used. ICallbackMessageProxyListener COM slots: 3 OnConnected, 4 OnDisconnected,
  5 OnPropertyChanged (from the CallbackAdapter dispatch at 0x166e8 and 0x1764c). WM QIs list items to
  IRemoteShellView {884EB994-3FDF-40FF-8800-AA1176F0F45E}; its slots are 9 NavigationLevel, 12 ProcessId
  and 19 ViewInstanceId.
- Upstream check: GitHub code search for "NavigationServer_ShellViewManager" across all repositories
  returned 0 hits (2026-10-08 ~18:55). That search is bounded negative evidence only. Wine, wine-staging,
  Proton and ReactOS contain no CoreUIComponents implementation to reuse.
