There is no unpatched build of this exact base, so every failure was attributed against the touched code.

Regressions found and fixed (both caused by the sprint patch, both now pass):
1. rpcrt4:ndr_marshall "rpcMsg.TransferSyntax should have been unset": the patch set TransferSyntax in
   NdrClientInitializeNew; native leaves it unset. The NDR 2.0 syntax is now recorded only in combase's in-process
   channel shortcut (ClientRpcChannelBuffer_GetBuffer, target_hwnd path), the one place where the stub receives the
   client message directly; the RPC runtime path builds a zeroed server message (rpc_server.c calloc), for which
   NdrStubCall3 already falls back to NdrStubCall2. ndr_clientserver.c is back to upstream.
2. rpcrt4:cstub "wrong proxy 1/3 func 0-2": the ndr3-rofill edit only filled NULL IUnknown slots; native overwrites
   writable tables. fill_delegated_proxy_table now overwrites writable tables and keeps pre-filled read-only ones
   (VirtualQuery). A compare-and-write variant was tried first and broke the original app (br40: access violation
   writing OneCoreUAPCommonProxyStub.dll .rdata from NdrDllGetClassObject; its pre-filled slots are the DLL's own
   import thunks, not rpcrt4 addresses). Native cannot write read-only data either.
